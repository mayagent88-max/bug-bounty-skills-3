# Work Through to a Result

## Define the finish line before you start

- Write down what done means for the task before you start work, such as every phase finished, a report submitted, or a waitlist joined, and keep that finish line visible in your working notes.

- List the phases or steps the work needs in order and name the evidence each phase must produce, so a finished phase is a fact you can point to and not a feeling.

- Note the checks you will run at the end, such as a live status check or a submitted confirmation, before you begin the first phase.

## Work phase to phase without pausing to ask

- Move from one phase to the next as soon as the current phase is done and do not stop to ask the user what to do next.

- Treat a phase boundary as a handoff inside your own work and not as a decision point for the user.

- When a phase ends with no finding or no lead, record that result and move to the next phase or close the task, instead of asking whether to continue.

- When a detail is uncertain, pick the best supported option, record the assumption in your notes, and keep working.

## Stop only on a real block

- Stop and ask the user only when the work is truly blocked, such as a missing account the user must create, funds the task needs, or a step that spends money or cannot be undone.

- Treat a stop order from the user as a hard stop, report the stopped state once, and do not offer a recovery choice unless the user asks for one.

- When you stop on a block, name the exact missing item and the smallest action that unblocks the work, so the user can answer once and the work can resume.

## Report the result once

- Report once when the work reaches its finish line or a real block, with the outcome, the evidence, and the next step for each project on its own.

- When the result is no finding, say so plainly with what you checked, instead of asking the user what to do about it.

- Save the result, the accounts, the links, and the status in the workspace file for the task, so the work survives a restart.

## Available connectors

- Use `muse.connector_search` to find other connectors and `muse.skill_search` to find related skills.

- If nothing here fits, look on the web for a maintained API or MCP server and set it up with [Custom Connectors and MCPs](/opt/muse/skills/custom-connector-setup/SKILL.md), or build a custom connector.

## Alternatives for better results

- When a phase needs a tool or a skill you have not used before, search for it and try the documented route first, and ask only when every route you found is blocked.

- When the user has already told you to work a task through to a result, treat that order as covering every phase of the task and not only the first one.
